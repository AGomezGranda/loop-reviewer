# Complete one initial review per developer and PR, then verify findings on demand

Across scans, interfaces and restarts, the coordinator resumes an existing run or draft for the same PR and revision. The initial review completes when the developer chooses “Finish locally” or GitHub confirms publication. History retains the reviewed revision, the final summary and retained findings, the verdict and the publication status. A completed PR stays out of the initial review queue.

Save the exact submission locally before sending it. After a rejection the developer can retry that submission under the same account while the revision is current. If the outcome is unknown, check GitHub for the original review first. If it is found, record the published review. If uncertainty remains, show the PR on GitHub and require an explicit decision before another submission. The [publication](0001-publish-reviews-through-gh.md) and [revision](0004-review-a-specific-revision.md) rules apply to retries.

Once follow-up is available, a new push on a completed PR with retained findings makes “Verify previous findings” available. The developer can request it from history for any reviewed PR, including a one-off, or from the inbox for a discovered update. Compare the final findings the developer kept with the new revision. For each, report “Appears fixed,” “Still present” or “Needs a human check” and the evidence or uncertainty behind that assessment. A line disappearing is insufficient evidence of a fix. Verification stays local and preserves the original review and publication record.
