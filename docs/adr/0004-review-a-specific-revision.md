# Hand the reviewer a specific PR revision

The coordinator records the repository, PR number, target branch, base tip, merge base and head commit at selection. It passes these to the reviewer port. Hosted Git intake fetches and verifies the selected commits in a private bare repository. The reviewer examines a sanitized object view pinned to that merge base and head, without a checkout. This keeps the engine replaceable and gives the developer a precise account of what was examined.

The reviewer returns a versioned report with an original recommendation, coverage, and verified findings in impact order. The hosted adapter projects those findings into editable feedback and saves the original report separately. A partial report can retain verified findings; no recommendation is not an approval. Each finding describes the triggering condition and consequence and links to the reviewed diff where possible. The publisher places retained findings inline where their locations are usable and includes the remainder in the final summary. Dropped findings must also be absent from the publication preview and submission.

If the target branch, merge base or head changes during review, keep the earlier draft local, explain what changed and offer to review the current revision. Recheck all three immediately before publication and retry. A base tip advancing on the same branch with an unchanged merge base and head leaves the reviewed comparison valid. Submit the reviewed head explicitly as the GitHub review’s commit so a concurrent push cannot silently attach feedback to a different revision.
